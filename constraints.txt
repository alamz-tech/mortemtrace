# Dependency lock for MortemTrace.
#
# pyproject.toml declares compatible version *ranges*, which is right for a
# library but insufficient for a deployable service: without pinning, two
# builds of the same commit can install different versions. That is not a
# hypothetical risk here - a google-adk minor release changed how model-call
# exceptions propagate through its sync Runner, which this codebase's retry
# and model-fallback behaviour depends on.
#
# GENERATED ON PYTHON 3.11 - the version the container and Cloud Run run.
# This matters: an earlier version of this file was frozen from a 3.13
# development environment and pinned grpcio to a release with no cp311
# wheel, which made `pip install -c constraints.txt` unresolvable inside
# the very image it was meant to pin. A lockfile must be generated on the
# runtime it locks.
#
# Regenerate after changing a dependency range in pyproject.toml:
#   docker run --rm -v "$PWD":/src -w /src python:3.11-slim sh -c \
#     'pip install -q -e ".[dev]" && pip freeze --exclude-editable' \
#     | grep -v "^-e\|^mortemtrace" | sort
#
# Then re-run the full suite on 3.11 before committing.
